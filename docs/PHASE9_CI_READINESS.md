# Phase 9 CI/testing readiness — audit only

## Implementation update — 2026-11-21

The audit below is historical. Phase 9 local implementation was subsequently authorized. `.github/workflows/quality.yml` now has three gates: isolated backend regression and `pip-audit`; frontend tests, TypeScript, ESLint, build and `npm audit`; disposable PostgreSQL migration/integration plus Playwright desktop/390px smoke. The browser job creates a random synthetic account and records only in its local CI database, then removes its fixture. No Neon credentials are used.

Local run commands:

```text
cd backend && .venv/Scripts/python.exe scripts/run_local_tests.py
cd frontend && npm test && npm run typecheck && npm run lint && npm run build
```

The PostgreSQL runner `backend/scripts/run_ci_postgres.py` requires the exact disposable localhost CI target and test environment; `frontend/e2e/ci-smoke.spec.ts` requires a fixture generated by `backend/scripts/ci_browser_fixture.py` in runner temp. Do not point these scripts at shared Neon. Local PostgreSQL integration and Chrome smoke passed on 2026-11-21; the GitHub-hosted workflow itself remains unrun and Phase 9 remains partial. See `PROJECT_PROGRESS.md` for counts and the fixture defect found during browser execution.

## แผนขั้นต่ำเมื่ออนุมัติ Phase 9

1. **PR gate แบบไม่ใช้ฐานข้อมูลภายนอก:** GitHub Actions รัน backend runner เดิม, frontend tests ทุกไฟล์, ESLint, `tsc --noEmit`, build และ `git diff --check` บน runtime versions ที่ตรวจเข้ากับ lockfiles แล้ว. เก็บ stdout/exit code และแยก job เพื่อระบุไฟล์/ชั้นที่ล้มเหลว.
2. **API/security integration:** ใช้ FastAPI TestClient และ fixtures ที่มีเพื่อยืนยัน auth/RBAC, BFF origin/forwarding, validation และ error contracts; เพิ่มเฉพาะช่องว่างที่พบจาก checklist ไม่สร้าง framework ซ้ำ.
3. **PostgreSQL concurrency gate แยก:** แก้ revision assertion เก่าให้ตรวจ migration head ที่ถูกต้องตาม branch และ fixture ownership/cleanup ก่อนรัน. ใช้ฐานข้อมูล/Neon branch ชั่วคราวที่ระบุชัดและได้รับอนุมัติสำหรับ state changes; ตรวจ shared limiter, stale conflict, atomic writes และ cleanup แม้ test ล้มเหลว. อย่าให้ PR ปกติยิง shared integration-test โดยอัตโนมัติ.
4. **Browser E2E ที่ทำซ้ำได้:** ย้ายเฉพาะ test ที่ให้คุณค่าสูงจากสคริปต์ชั่วคราวเข้าสู่ repository พร้อม isolated synthetic fixture/auth setup: login, Monitoring filter/sort/Detail/Back, Case evidence, RBAC, logout/401, desktop/390px. เก็บภาพและ network status แบบลบ token/cookie; ห้าม commit browser profile หรือ credential.
5. **Dependency/security gate:** กำหนด `pip-audit` และ `npm audit` จาก dependency manifests/lockfile หลังตรวจเวอร์ชันและนโยบาย fail ที่เหมาะสม; แสดง package/advisory และคำสั่งที่ล้มเหลว ไม่ใช้บริการ/API เสียเงิน.

ก่อนลงมือให้เจ้าของอนุมัติขอบเขต Phase 9, runtime/CI provider และวิธีจัดหา PostgreSQL/Neon branch แยกพร้อมสิทธิ์ cleanup. ไม่มี migration, seed หรือ CI workflow ถูกสร้างใน audit นี้.
